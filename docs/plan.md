# 화면 피드백 SDK 구현 계획

**Goal:** SitePing의 웹 앵커를 활용한 서버 없는 웹·앱 SDK와 실행 예제 제공.

**Architecture:** 플랫폼에 독립적인 어댑터 계약·메모리 구현을 공유하고 React와 React Native 렌더러를 분리함. 사용자 인증·저장·사진 업로드는 호스트가 연결함.

**Tech Stack:** TypeScript, React 19.1, React Native 0.81.5, Expo 54, npm workspaces, Node 24 테스트, Vite 웹 예제.

**Spec:** [design.md](design.md)

## 전역 제약

- 별도 서버·DB·로그인·관리사이트를 만들지 않음.
- 기존 목업의 기능과 후속 수정을 보존하며 프로젝트 이름과 브랜치·커밋에 실행 도구의 이름이나 크레딧을 넣지 않음.
- LINKUS 코드·브랜드·스크린샷·실데이터를 공개 저장소에 복사하지 않음.
- SitePing 원저작권·MIT 고지·기준 커밋·수정 내역을 보존함.
- 생성 결과를 직접 편집하지 않고 소스에서 재빌드함.

## 검토 중점

- 화면이나 계정 전환 뒤 이전 댓글·초안이 나타나지 않는지 확인함.
- 드래그와 길게 누르기가 기존 클릭·스크롤·입력을 방해하지 않는지 확인함.
- 권한 취소·비동기 응답 순서 변경 때 쓰기와 표시가 안전하게 끝나는지 확인함.
- 앱 모달·가상 목록에서 다른 요소에 핀이 붙지 않는지 확인함.
- 사진 보기 종료 뒤 초안·초점·원래 화면이 유지되는지 확인함.

## 작업

- [x] 공통 코어: 기존 초안 재검증, 새 댓글의 해결 상태와 로컬 사진 계약 보완, 예제용 어댑터 검증.
- [x] 웹 SDK: SitePing 앵커를 실제 사용하도록 연결, 이동·접기·편집·삭제·알림·사진 확대 기능 완성, React DOM 동작 테스트와 웹 예제.
- [x] 앱 SDK: Provider·Surface·Anchor 공개 API, 네이티브 위치 측정과 길게 누르기, 동일 기능 UI·사진 보기·접기·이동, 컴포넌트 테스트와 Expo 예제.
- [x] 패키징: 루트 workspace·빌드·정적 검사·MIT 고지·연동/보안 문서와 CI 구성.
- [x] 검증 및 전달: 독립 리뷰, 필요한 수정과 재검증, 각 패키지 pack, 기능 브랜치 푸시와 Draft PR 생성.

## 작업 분리

공통 계약의 변경은 additive로 제한함. 패키지별 구현 파일은 서로 다른 작성자가 맡고 루트 설정·설치·Git·문서는 메인 작업자가 맡음. 공통 의존성 설치와 커밋을 동시에 실행하지 않음.

앱 컴포넌트 검사와 Android·iOS 번들 생성은 완료했으나 실기기 검증은 실행 환경 부재로 남음. SDK 설치·대상 기기 검증과 서비스의 실제 어댑터 연결은 별개임.

구현은 [Draft PR #2](https://github.com/won005/screen-feedback/pull/2)로 전달함. 코어 26개·웹 25개·앱 15개 테스트, 전체 타입·빌드, 3개 tarball과 양 플랫폼 Metro export 검사 완료. 실제 웹 브라우저와 독립 리뷰의 확인 범위는 루트 README의 검증 범위에 명시함.
