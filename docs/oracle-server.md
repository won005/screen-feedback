# Oracle 피드백 서버 설계

기존 SDK를 Oracle Always Free ARM 서버에 연결해 웹·앱이 같은 댓글·사진·알림을 공유하도록 함. 메모리 SDK는 그대로 제공하고 Node 24 서버와 HTTP 어댑터를 별도 패키지로 추가함. 무료 서버 선택은 사용자 결정이며, 아래 구현 기술은 기존 TypeScript SDK와 작은 단일 인스턴스에 맞춘 구현 선택임.

## 구성과 대안

Oracle ARM 2 OCPU·RAM 12GB의 무료 범위를 사용함. 기존 AWS/Supabase 제안 대신 사용자가 Oracle을 선택함. 다중 DB·외부 파일 서버보다 단일 SQLite와 Docker Compose를 사용해 초기 운영 대상을 줄임. SQLite 안에 사진 바이트와 프로젝트 상태를 함께 보존하고 백업함. PostgreSQL·오브젝트 스토리지로의 확장은 이번 구현에 포함하지 않음.

프로젝트별 상태 변환은 기존 core의 권한·상태·알림 규칙을 재사용함. 신뢰된 서버만 읽는 버전 있는 상태 스냅샷을 추가하며, 각 쓰기는 SQLite 트랜잭션 안에서 검증·실행·저장함. 트랜잭션 성공 후에만 변경 알림을 보냄. 프로세스 1개와 서버 복제본 1개만 지원함. 사진은 최대 5MB, 프로젝트별 256MB, 댓글 상태는 프로젝트별 8MB로 제한함.

## 신원과 권한

호스트 서비스가 발급한 짧은 수명의 JWT를 사용함. 서버에 고정한 HTTPS JWKS·issuer·audience와 exp를 검증하고 sub를 계정 ID로 사용함. 클라이언트가 작성자·권한·프로젝트 멤버 목록을 지정할 수 없음. 운영자 CLI로 프로젝트를 만들고 허용 계정·표시 이름·관리자 여부를 지정함. 관리 HTTP API·별도 로그인 화면·관리사이트는 이번 범위 밖임. 실제 호스트 인증 제공자의 설정은 배포 전에 연결해야 함.

모든 읽기·쓰기·사진·실시간 연결에서 프로젝트 멤버십을 확인함. 권한 회수는 다음 요청과 실시간 주기 검사에 반영함. CORS는 명시한 웹 출처만 허용하고 앱도 동일한 bearer 검증을 거침. 비밀키를 SDK나 예제 번들에 포함하지 않음.

## 연결 계약

- `POST /v1/projects/:projectId/rpc`: bearer JWT, `{method,args}`. 메서드는 `FeedbackAdapter` 중 `subscribe`, `uploadAttachment`를 제외한 명시 목록만 허용함. 응답은 `{result}` 또는 `{error:{code,message}}`임. getAccess는 미등록 계정을 allowed=false로 반환함. 다른 데이터는 접근 거부함.
- `POST /v1/projects/:projectId/photos`: bearer JWT, 이미지 바이트와 Content-Type·X-File-Name. 파일 시그니처·크기를 확인하고 서버가 생성한 사진 ID와 메타데이터를 반환함. 댓글 등록 시 해당 프로젝트·작성자가 업로드한 사진만 연결함. 외부·로컬 URL이나 위조 메타데이터를 저장하지 않음.
- `GET /v1/projects/:projectId/photos/:photoId?ticket=...`: 짧은 수명의 사진 전용 서명 URL. 티켓은 사진·프로젝트·계정·만료에 묶고 현재 멤버십·레코드 접근을 확인함. URL이 로그에 기록되지 않도록 프록시 접근 로그를 사용하지 않음. 댓글 응답마다 새 URL을 발급함.
- `/v1/events`: WebSocket. 연결 직후 JWT·projectId 인증 메시지를 받고 성공 전에는 아무 데이터도 전달하지 않음. JWT 만료·권한 회수 시 접근 변경 이벤트 후 종료함. 클라이언트는 재연결 시 현재 토큰을 다시 받아 인증함. 이벤트에는 댓글 본문·사진·계정 목록 없이 changed/access-changed만 포함함.

HTTP 어댑터는 `baseUrl`, `projectId`, `getToken`, 선택적 `fetch`/`WebSocket`을 받음. 인증 토큰은 각 요청 때 호스트 콜백에서 받음. 웹 Blob 또는 `{bytes,name,mimeType}` 사진을 업로드하며 앱 파일 읽기는 호스트가 제공함. 읽기 실패·쓰기 실패를 자동 성공 처리하지 않고, 쓰기는 암묵 재시도하지 않음. 구독이 다시 연결되면 재조회 이벤트를 보냄.

사진은 서버가 ID로 찾은 고정 메타데이터만 스냅샷·재시도 수신 기록에 저장하고 HTTP 응답 복사본에 서명 URL을 발급함. HTTP와 WebSocket은 exp와 iat+1시간 중 이른 시각까지 유효함. 계정 ID는 앞뒤 공백을 허용하지 않고 원문 sub와 정확히 일치시킴. 정상 요청은 계정·프로젝트별 분당 180회, 전체 서버 보호 한도는 별도로 분당 6,000회임. 외부에서 보낸 Forwarded 헤더를 신뢰하지 않음.

## Oracle 배포와 검증 경계

Ubuntu ARM64, 영구 데이터 볼륨, 비루트 Node 컨테이너와 Caddy HTTPS 프록시를 사용함. 인터넷에 공개하는 앱 포트는 80/443이며 서버 8080은 Docker 내부에 둠. SSH는 운영자 주소로 제한함. 무료 대상 표시와 금액을 확인하고 자원 부족 시 유료 VM으로 자동 대체하지 않음. Oracle 콘솔 로그인·홈 리전·DNS·인증 제공자 설정을 확보한 후 실제 생성·배포함.

재시작 보존·사진 바이트 보존·트랜잭션 실패·권한 회수·프로젝트 격리·JWT 위조·만료·CORS·위조 첨부·경로 접근·실시간 만료·백업 복구를 테스트함. 로컬 서버 검증, ARM 이미지 빌드, 실제 Oracle 배포와 실기기 검증은 각각 구분해 기록함.
