# 서버 없는 화면 피드백 SDK

## 목적과 승인 범위

웹과 React Native 앱에 Figma처럼 위치별 댓글을 붙이는 독립 MIT SDK를 제공함. 사용자가 승인한 빨간색 목업과 후속 수정 사항을 구현함. 자체 API·DB·사진 보관 서버·로그인·테스터 관리·관리사이트는 제외함. 기존 LINKUS 저장소와 화면 자료는 공개 소스에 포함하지 않음.

저장소는 `won005/screen-feedback`, 구현 브랜치는 `feat/siteping-sdk`를 사용함. 패키지는 `@won005/feedback-core`, `@won005/feedback-react`, `@won005/feedback-react-native`로 나눔.

## 기반 선택

- SitePing의 웹 DOM 앵커 생성·재탐색 구현을 MIT 고지와 함께 재사용함. 기준 upstream은 `NeosiaNexus/SitePing`의 `fd64185eda976c13c2c5e9a5fa20debf077b9004`임.
- SitePing 전체 서버·대시보드 포크와 완전 신규 구현을 비교했으며, 사용자가 선택한 서버 없는 SDK 범위에 맞춰 웹 앵커만 재사용하고 UI·공통 어댑터·네이티브 렌더러를 분리함.
- 화면 텍스트·폼 값·URL·콘솔·네트워크·화면 캡처는 자동 수집하지 않음. SitePing 앵커도 이 기본값에 맞춰 텍스트 문맥과 민감한 선택자를 저장하지 않도록 변경함.

## 사용자 동작

1. 웹 루트 또는 앱 루트에 SDK를 설치하고 호스트의 어댑터·현재 화면 식별자를 전달함.
2. ON 상태에서 웹은 우클릭, 앱은 길게 눌러 새 핀과 작성창을 엶. 스크롤·일반 클릭은 기존 앱 동작을 유지함.
3. 작성창 바깥을 누르면 창과 미등록 핀을 닫음. 등록된 핀은 유지함.
4. 툴바와 댓글창을 각각 자유롭게 이동함. 툴바는 작은 아이콘으로 접고 다시 펼칠 수 있음. 별도 새 댓글 + 버튼과 댓글 목록 버튼은 두지 않음.
5. 사진 선택·썸네일·전송 전 제거·사진만 등록·등록 사진 크게 보기를 제공함. 실제 업로드는 호스트가 제공하며 기본 예제는 선택한 사진을 기기 메모리에서만 유지함.
6. 댓글·답글마다 작은 선 아이콘으로 좋아요·수정·삭제를 제공함. 본인만 수정하며 삭제 권한은 어댑터가 결정함. 질문 삭제는 답글까지 함께 삭제하고, 답글 삭제는 해당 답글만 삭제함. 등록된 데이터 삭제는 확인창을 거침.
7. 새 댓글창과 기존 댓글창 상단에 해결·삭제를 제공함. 초안의 해결 선택은 등록 상태에 반영하고, 초안 삭제는 작성 내용을 지움. 해결된 질문은 다시 열 수 있음.
8. @사용자 선택과 알림함을 제공함. 댓글·답글·멘션 알림은 어댑터가 공급하며 읽음 표시와 해당 질문 이동을 제공함. 다른 화면으로의 이동은 호스트 콜백이 담당함.
9. 답글 등록과 댓글 수정에 성공 토스트를 띄우지 않음. 작성 안내 글자는 작게 표시함.

## 계약과 책임

`packages/core/src/types.ts`의 `FeedbackAdapter`를 공통 계약으로 사용함. 읽기·쓰기·삭제·좋아요·알림·구독·선택적 사진 업로드를 호스트가 구현함. 메모리 어댑터는 서버 없는 예제와 테스트용이며 네트워크 인증 경계로 사용할 수 없음. 권한 신호는 UX용이며 실제 서버를 연결하면 매 요청에서 신원을 확인하고 권한을 검증해야 함.

화면은 `id + resourceId`로 분리하며 버전은 작성 문맥으로 보존함. 화면 전환·사용자/어댑터 전환 때 이전 댓글이나 작성 상태가 섞이지 않아야 함. 안정된 위치가 필요한 요소는 웹 `data-feedback-anchor`, 앱 `FeedbackAnchor`로 등록함. 찾지 못한 요소에 핀을 임의로 붙이지 않음.

패키지는 자동 네트워크 호출·비밀키·추적 기능을 포함하지 않음. 이미지 URL은 호스트 책임이며 SDK에서 실행 가능한 URL이나 HTML을 해석하지 않음. 저장 실패·권한 취소·버전 충돌은 성공으로 표시하지 않음.

## 검증과 배포

공통 어댑터의 상태·삭제·권한·알림 경계, 웹 DOM·상태 전환·파일 확대, 앱 렌더링·제스처·키보드·화면 전환을 검증함. 웹 데모와 Expo 예제를 제공하고 빌드·타입 검사·패키지 pack을 수행함. Android/iOS 실제 기기 검증 범위는 자동 테스트·웹 시뮬레이션과 구분해 기록함.

검증된 소스를 기능 브랜치에 게시하고 Draft PR로 전달함. npm 게시·운영 배포·LINKUS 실제 연동은 이 첫 SDK 구현의 배포 범위에 포함하지 않음.
